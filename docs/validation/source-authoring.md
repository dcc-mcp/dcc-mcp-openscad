# Source authoring publication validation

The [selected source qualification](source-authoring-native.json) records actual adapter-class MCP write, inspect, validate and native export calls on OpenSCAD 2021.01 and official Core/server/CLI 0.20.41. Independent readback found 8 vertices and 6 OFF faces with bounds 3×5×7, a parameter variant with bounds 4×5×7, and a 684-byte binary STL with 12 facets. Seven negative requests left the original source unchanged and created no negative artifact.

The receipt describes the handed-off source snapshot. Its privacy transformations, raw trace byte count, event count and SHA-256 are declared in the JSON. Public artifact paths are relative roles; the real API requires absolute paths within configured roots. The private raw trace is not included. Direct CLI checks are separate from actual MCP requests.

Publication review subsequently rejects Windows alternate streams, reserved devices and trailing dots/spaces, with version-stable device-name handling and regressions. Bounded pytest parameter IDs avoid serializing oversized inputs into process environment variables. Initial publication checks passed Ruff lint/format, sdist/wheel builds and Twine on Windows Python 3.12 / Core 0.20.41. That complete local run reported 145 passed, 9 skipped and 3 failures in unchanged process-lifecycle tests. The isolated lifecycle regression and five equivalent synthetic runs passed, but did not replace a green full suite.

The source snapshot's full suite retained one existing PNG-preview failure on its headless host. Supported OpenSCAD native CI must execute and pass its PNG/STL assertions without skips on the final PR head before merge. No GUI acceptance or release is claimed.

Formal review adds rejection of the legacy `import_stl`, `import_dxf` and `import_off` primitives. Source bytes are written, synchronized and read back through an owned temporary descriptor before exclusive hard-link publication. Existing or concurrently created destination files are preserved. Temporary and published file identities are checked; failure cleanup never unlinks the public destination. The workspace must support hard links. Temporary cleanup is best-effort and can leave a staging file after a system unlink failure; path/identity checks assume a controlled workspace and do not establish atomic protection against hostile concurrent path or same-file mutations.

These review fixes pass 41 focused authoring tests with no skips, Ruff lint/format and Python 3.7 grammar checks. The fresh full local suite reports 161 passed, 9 skipped and 5 failures in unchanged process-lifecycle tests; source authoring tests all pass. Fresh wheel/sdist and Twine checks also pass. Actual Python 3.7 and supported native acceptance remain requirements of the new PR HEAD's CI.
